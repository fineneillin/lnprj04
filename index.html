方向四 · 系統架構

背後怎麼運作的

整個系統分成五層，訊息從你的手機出發，一路到存進知識庫，每個環節都有對應的工具負責。

1
使用者端 — 你的 LINE
你透過 LINE App 傳送訊息，可以是任何形式：文字、網址、語音、圖片，甚至只是一個隨手的想法。
LINE App（iOS / Android）
文字 / 網址
語音訊息
圖片 / 截圖
隨手想法
↓  HTTPS Webhook
2
通訊閘道 — LINE Messaging API
LINE 官方提供的 Messaging API，把你傳的每一條訊息透過 Webhook 即時轉發到你的伺服器。這是整個系統的「門鈴」，訊息進來它就響。
Messaging API（官方）
Webhook Event
Channel Token 驗證
Reply API
↓  HTTP POST（JSON）
3
應用伺服器 — VPS 上的 Python
跑在雲端 VPS 的 Python 應用（FastAPI），是整個系統的「調度中心」。它接收訊息後判斷類型，決定要交給哪個 AI 模組處理，24 小時在線。
FastAPI（Python）
訊息類型路由
URL 內容抓取
任務排程
錯誤處理
↓  API 呼叫
4
AI 處理層 — Claude + Whisper
兩個 AI 模型各司其職。Claude 負責理解文字與圖片、生成摘要、自動打標籤、回答查詢；Whisper 專門把語音訊息轉成文字後再交給 Claude。
Claude API（理解 / 視覺 / 生成）
Whisper API（語音 → 文字）
自動摘要
自動標籤分類
語意搜尋
↓  讀寫
5
儲存層 — 你的知識庫
所有整理好的知識都存在 SQLite 資料庫裡。每筆記錄包含原始內容、AI 摘要、標籤、來源類型、時間戳記，讓你可以用自然語言問問題找到它。
SQLite 資料庫
原始內容
摘要 + 標籤
語意嵌入向量
時間軸索引

兩種核心流程

📥 存入流程（你傳訊息）

1
你在 LINE 傳送訊息（文字 / 語音 / 圖片 / 網址）
2
LINE API 把訊息 POST 到你的 VPS
3
伺服器判斷訊息類型並路由
4
語音 → Whisper 轉文字；圖片 → Claude Vision 讀取
5
Claude 生成摘要並自動打標籤
6
存入 SQLite，LINE 回覆「✅ 已儲存」確認

🔍 查詢流程（你問問題）

1
你在 LINE 用自然語言問問題
2
伺服器識別為「查詢」指令（非存入）
3
Claude 把問題轉成語意向量
4
從 SQLite 找出最相關的知識片段
5
Claude 綜合片段生成自然語言回答
6
LINE 回覆答案 + 引用來源筆記
